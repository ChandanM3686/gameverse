# GameVerse

**Prompt it. Play it.** GameVerse turns a plain-English game idea into a playable 3D browser game. An AI agent asks a few design questions, writes three.js code into the game's own workspace, and the result plays live next to the chat.

## Stack

| Layer | Tech |
| --- | --- |
| Frontend | Next.js 16 (App Router), React 19, Tailwind CSS v4, shadcn/ui |
| AI model | Google Gemini via the Vercel AI SDK (`streamText` + tool calling) |
| Durable agent runs | Trigger.dev `chat.agent` (long-running turns, resumable streams, retries) |
| Database | SQLite (Node's built-in `node:sqlite`), file at `.data/gameverse.db` |
| Game files | One folder per game at `.data/games/<id>/`, served by a Next.js route |

## Getting started

```bash
npm install --ignore-scripts
cp .env.example .env.local     # GOOGLE_GENERATIVE_AI_API_KEY, TRIGGER_SECRET_KEY, TRIGGER_PROJECT_REF
npx trigger.dev@latest login   # once
npm run trigger:dev            # terminal 1: Trigger.dev worker (runs the AI agent)
npm run dev                    # terminal 2: http://localhost:3000
```

Requires Node 24+ (for `node:sqlite`). The database and tables are created automatically on first run.

## How it works

1. **Create**: the home page saves a game row in SQLite (title generated by Gemini) and opens `/games/[id]`.
2. **Session**: a server action starts a Trigger.dev chat session and gives the browser a short-lived token scoped to that one game.
3. **Workspace**: on the first turn, the Trigger worker copies a starter three.js engine (`lib/games/runtime`) into the game's folder.
4. **Brief**: the agent uses the `ask_player` tool to ask design questions one at a time. The turn pauses until the player picks an answer.
5. **Build**: Gemini writes code with file tools (`list_files`, `read_file`, `write_file`, `replace_text`, `delete_file`). Every path is checked so it stays inside the game's folder.
6. **Preview**: `/play/[id]/...` serves the game's files and the page shows them in an iframe. Runtime errors are reported back to the chat.
7. **Persist**: each finished turn saves the messages and the stream position, so a page reload picks the stream back up.

## Project structure

```text
app/                 home, game page, preview API, /play file server
components/          chat thread, composer, preview, sidebar, UI primitives
lib/db/              SQLite client and Game type
lib/workspace/       per-game folders (create, find, delete)
lib/games/           agent prompt, tools, Gemini models, chat persistence, starter engine
trigger/chat.ts      the Trigger.dev chat agent (game-chat)
```

## Storage

Games and every game file live in the database (`games` and `game_files` tables). Without `DATABASE_URL` the app uses a local SQLite file; with it, Postgres. The Next.js server and the Trigger.dev worker share that one database, which is what lets them run on different machines.

## Deploy (Render + Trigger.dev)

1. Push the repo to GitHub.
2. Render → **New → Blueprint** → pick the repo. `render.yaml` creates the web service and a Postgres database.
3. Set the secret env vars on the web service: `GOOGLE_GENERATIVE_AI_API_KEY`, `TRIGGER_SECRET_KEY` (the **prod** key, `tr_prod_...`), and `APP_PASSWORD`.
4. Trigger.dev dashboard → Production → Environment variables: add `GOOGLE_GENERATIVE_AI_API_KEY` and `DATABASE_URL` (the Render database's **External** URL).
5. Deploy the agent: `npx trigger.dev deploy`.
6. Render → web service → Settings → **Custom Domains** → add your domain and the DNS record it shows.
